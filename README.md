# Facebase - Personalized Displays with Face Recognition

> **Learning project.** I'm building this to explore Rust, PostgreSQL vector search, face recognition, and web development. It isn't meant to compete with commercial products.

> 🚧 **Work in progress.** The CLI works end to end. The web app and live camera parts are not built yet. See [ROADMAP.md](ROADMAP.md) for current status.

Facebase recognizes the person in front of a camera and shows them a personalized display, such as a greeting, weather, to-dos, or calendar, generated by an LLM from their profile. Unknown faces get a generic guest view.

## How it works

1. **Register:** give a photo and a name. The face embedding is stored in Postgres (pgvector) and linked to that person's profile.
2. **Recognize:** a new photo is embedded and compared against the stored embeddings using cosine distance. If the closest match is under the threshold, that person is identified. Otherwise they're treated as a guest.
3. **Personalize:** the recognized person's profile is sent to Claude, which writes their personalized output.
4. **Display:** the output appears in a web page *(planned)*, and eventually updates live based on who is in front of the camera *(planned)*.

### Architecture (target)

```
browser (web page + webcam)
        │  POST /recognize (image)
        ▼
Rust server (axum)  ──▶  Python embedding (DeepFace / ArcFace)
        │
        ├──▶  PostgreSQL + pgvector  (people, face embeddings)
        └──▶  Claude API             (personalized output)
```

- **Rust** (`organizer/`): CLI, web server *(planned)*, database, and LLM logic
- **Python** (`python/`): generates face embeddings with [DeepFace](https://github.com/serengil/deepface)
- **Frontend** *(planned)*: plain HTML + JS, no framework

## Prerequisites

- Rust (via [rustup](https://rustup.rs))
- PostgreSQL with the [pgvector](https://github.com/pgvector/pgvector) extension
- [uv](https://docs.astral.sh/uv/), which manages the Python environment and DeepFace
- An [Anthropic API key](https://console.anthropic.com/)

## Setup

### Environment

Create a `.env` file in the repo root:

```bash
ANTHROPIC_API_KEY=your-key-here
```

### Python

The Rust binary shells out to `uv run` for the embedding script, so you don't need to activate a virtualenv yourself. uv reads `python/pyproject.toml` and creates `python/.venv` automatically on the first run.

To pre-install the dependencies (optional; otherwise this happens on the first run):

```bash
cd python
uv sync
```

uv installs the pinned Python (`3.13`) and DeepFace + TensorFlow into `python/.venv`. The first `DeepFace.represent` call also downloads the ArcFace and RetinaFace model weights.

### Database

The tool connects to a local PostgreSQL database named `photos` as the current `$USER`.

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE people (
    id      SERIAL PRIMARY KEY,
    name    TEXT UNIQUE NOT NULL,
    profile JSONB
);

CREATE TABLE face_embeddings (
    id                SERIAL PRIMARY KEY,
    person_id         INTEGER REFERENCES people(id),
    embedding         vector(512),
    source_image_path TEXT
);
```

`profile` holds the information the LLM uses to personalize output, such as interests, location, or to-dos. For now you fill it in manually.

## Usage

### CLI (works today)

Run these from the `organizer/` directory:

```bash
# Register a person (the photo is deleted after registration)
cargo run -- register path/to/photo.jpg --name "Alice"

# Recognize a face and print personalized output
cargo run -- recognize path/to/unknown.jpg
```

> ⚠️ `register` deletes the source photo after storing the embedding. Don't point it at your only copy.

### Web app (planned)

```bash
cargo run -- serve
```

Then open `http://localhost:3000`, upload a photo, and see the personalized output. A later version will use the webcam to recognize whoever is in front of the camera automatically.

## Known limitations

- Each recognition starts a fresh Python process, which reloads TensorFlow and takes several seconds. A long-running embedding service is planned for live camera mode.
- The match threshold (cosine distance `0.4`) is hardcoded.
- Only the first confidently detected face in a photo is used.
